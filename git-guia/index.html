Arquitetura

As quatro áreas do Git

Todo comando de Git move mudanças de uma área para outra. Clique numa área para saber o que ela é, ou num comando para ver para onde ele leva as coisas.

git add

O que tem dentro da pasta .git

Quando você roda git init, o Git cria uma pasta escondida chamada .git dentro do seu projeto. Ela é o repositório. Apague essa pasta e o projeto volta a ser uma pasta comum, sem histórico.

Cada commit é uma foto do projeto inteiro, não só das mudanças. Para não ocupar espaço, o Git guarda cada conteúdo de arquivo uma única vez: se o logo.png não mudou em 50 commits, existe uma cópia só dele.

Cada foto ganha um código único, o hash (ex.: c09e4a1), calculado a partir do conteúdo. Cada commit também lembra quem veio antes dele (o "pai"). É essa corrente de pais que forma o histórico.

Uma branch é só uma etiqueta com o nome e o hash do commit mais recente dela. Por isso criar branch é instantâneo.

site/
├── index.html        # seus arquivos (pasta de trabalho)
├── style.css
├── .gitignore        # o que o Git deve ignorar
└── .git/             # o repositório em si (escondido)
    ├── HEAD          # "você está aqui": ref: refs/heads/main
    ├── index         # o palco (staging area)
    ├── objects/      # todas as fotos: arquivos, pastas, commits
    ├── refs/
    │   ├── heads/     # suas branches: main, menu...
    │   │   └── main  # conteúdo: e41a9c2... (só um hash!)
    │   └── remotes/   # última posição conhecida do GitHub
    │       └── origin/main
    └── config        # endereço do remoto, configurações

    Gerenciando projetos

    Como usar Git num projeto de verdade

    A regra geral: um projeto, um repositório. A pasta raiz do projeto vira o repositório, e tudo o que está dentro dela é versionado junto.

    Trabalhando sozinho

    1. Comece o dia trazendo o que estiver no GitHub (se você usa mais de um computador).

      git pull

    2. Trabalhe normalmente nos arquivos, no editor que você já usa.

    3. Confira o que mudou antes de salvar a versão.

      git status git diff

    4. Coloque no palco e faça o commit com uma mensagem clara.

      git add . git commit -m "Adiciona formulário de contato"

    5. Envie para o GitHub. Isso é o seu backup.

      git push

    Trabalhando em equipe (com Pull Request)

    1. Atualize a main antes de começar.

      git switch main git pull

    2. Crie uma branch para a tarefa, com nome que descreve o que é.

      git switch -c feature/formulario-contato

    3. Faça commits pequenos conforme avança.

      git add . git commit -m "..."

    4. Envie a branch para o GitHub.

      git push -u origin feature/formulario-contato

    5. No site do GitHub, abra um Pull Request: o pedido para juntar sua branch na main.

    6. Colegas revisam, comentam, e você ajusta com novos commits na mesma branch.

    7. Aprovado, alguém clica em Merge. Depois você volta para a main, faz git pull e apaga a branch.

      git branch -d feature/formulario-contato

    Mensagens de commit que ajudam

    Escreva como se completasse a frase "Este commit…". Verbo no presente, curto, dizendo o que mudou.

    ✗update
    ✗agora vai
    ✗mudanças várias
    ✓Adiciona página de contato
    ✓Corrige link quebrado no rodapé
    ✓Remove imagens não usadas

    Muitas equipes usam prefixos: feat: (novidade), fix: (correção), docs:, style:, refactor:. É o padrão "Conventional Commits".

    Quando fazer commit?

    • Sempre que algo funciona e você não quer perder. Pense em "ponto de salvamento" de videogame.
    • Um commit, uma ideia. "Adiciona menu" e "corrige rodapé" são dois commits.
    • Antes de uma mudança arriscada, faça commit ou crie uma branch.
    • Não espere o fim do dia. Commits pequenos são fáceis de entender e de desfazer.

    Nomes de branch comuns

    • main versão estável, a que está no ar
    • develop em algumas equipes, onde as coisas se juntam antes da main
    • feature/nome funcionalidade nova
    • fix/nome ou bugfix/nome correção
    • hotfix/nome correção urgente direto em produção
    • release/1.2 preparação de uma versão

    Primeira configuração (uma vez por computador)

    # seu nome e e-mail vão em cada commit
git config --global user.name "Seu Nome"
git config --global user.email "voce@email.com"
# nome padrão da branch principal
git config --global init.defaultBranch main

    Para começar um projeto existente: entre na pasta pelo terminal (cd caminho/da/pasta) e rode git init. Para baixar um do GitHub: git clone URL.

    Se você prefere não usar o terminal

    • VS Code tem uma aba "Source Control" que faz add, commit, push e pull com cliques.
    • GitHub Desktop é um programa gratuito, bem visual, ótimo para começar.
    • Os botões fazem os mesmos comandos deste guia. Entender os nomes aqui faz os botões fazerem sentido.
